# Campanhas pela API oficial do WhatsApp

Este código prepara o envio e o menu de atendimento no painel do proprietário. Ele não está ativo na produção apenas por estar no repositório. Verificar primeiro se a base `149_platform_communications_foundation.sql` já foi aplicada; as migrations `150_platform_whatsapp_campaign_runs.sql` e `152_platform_whatsapp_bot.sql`, as funções e o frontend exigem aprovações de implantação separadas conforme `CLAUDE.md`. A migration 150 também cria o bucket público `communication-covers`, restrito a imagens enviadas pelo proprietário. Não colocar dados de alunos nessa área.

## Dependências externas

1. Manter um único número público para novidades e atendimento: o número atualmente usado no aplicativo WhatsApp Business. Para mantê-lo também no aplicativo, conectar pelo fluxo de coexistência de um provedor habilitado. Não registrar um segundo número como remetente das campanhas nem remover a conta atual sem decisão específica do proprietário.
2. Escolher `WHATSAPP_API_PROVIDER=meta` para conexão direta (padrão) ou `WHATSAPP_API_PROVIDER=dualhook` para coexistência pelo Dualhook. O segundo usa endpoint Graph compatível `api.dualhook.com` e uma chave de conexão `DUALHOOK_API_KEY`; no fluxo direto usa-se `META_WHATSAPP_ACCESS_TOKEN`. Em ambos, registrar os IDs reais da WABA e do número **após** a conexão, não presumir que o ID do ativo atual sirva para a API. Configurar a cobrança da Meta conforme as tarifas vigentes; Dualhook cobra assinatura à parte.
3. Criar e aprovar na Meta pelo menos um modelo de categoria adequada. Para esta versão, ele deve ter um corpo de texto com `{{1}}`, pode ter cabeçalho de imagem e botões de URL variável cujo endereço termina com `{{1}}`. O painel pede um destino para cada botão variável; cada destino precisa manter o prefixo aprovado pela Meta. Os rótulos e tipos de botão são definidos no modelo aprovado, não livremente a cada disparo. Um botão de resposta rápida “Falar com atendente” pode acionar o atendimento humano no mesmo número.
4. Configurar os segredos de backend `META_WHATSAPP_WABA_ID`, `META_WHATSAPP_PHONE_NUMBER_ID`, `META_WHATSAPP_VERIFY_TOKEN`, `META_WHATSAPP_GRAPH_VERSION` e `ALLOWED_ORIGINS` com o domínio oficial do painel. No modo direto, configurar `META_WHATSAPP_ACCESS_TOKEN` e `META_WHATSAPP_APP_SECRET`. No modo Dualhook, configurar `DUALHOOK_API_KEY` e `WHATSAPP_WEBHOOK_URL_SECRET` com uma chave aleatória de pelo menos 32 caracteres. Nunca colocar token no JavaScript público.
5. Implantar `platform-whatsapp-campaign` com verificação de JWT e `platform-whatsapp-webhook` sem verificação de JWT. No modo direto, cadastrar a URL na Meta e assinar o campo `messages`; cada POST exige assinatura HMAC SHA-256 com o App Secret. No modo Dualhook, cadastrar o override do webhook como `https://<projeto>.supabase.co/functions/v1/platform-whatsapp-webhook?key=<WHATSAPP_WEBHOOK_URL_SECRET>` e o mesmo `META_WHATSAPP_VERIFY_TOKEN` para o desafio GET. O Dualhook informa que a assinatura da Meta usa o segredo do aplicativo dele, que não é compartilhado: esse modo valida a URL secreta, WABA ID e Phone Number ID, mas **não oferece autenticação criptográfica do corpo**. Tratar a URL como credencial, limitar sua divulgação e girá-la se vazar. Não ativar o bot até testar um POST real e confirmar esse risco.

## Operação

No painel, salvar o rascunho, escolher o modelo aprovado, fazer a prévia e confirmar o envio. O público é deduplicado por usuário e inclui apenas contas ativas em escolas ativas, com aceite de WhatsApp e número válido. O limite inicial é de 100 pessoas por campanha. Uma reserva única por campanha impede disparo duplicado, inclusive após falha parcial. Cada chamada aceita pela Meta recebe um ID no histórico; o webhook atualiza entrega/falha e aplica respostas `SAIR` ou `PARAR` às preferências do número.

A mensagem digitada entra em `{{1}}` do modelo e aceita até 500 caracteres. A imagem precisa ser HTTPS e corresponder a um modelo com cabeçalho de imagem. Cada link de destino precisa ter o prefixo aprovado no respectivo botão de URL variável. A Meta decide a categoria e os preços do modelo. A prévia mostra a categoria, mas a cobrança final depende das mensagens entregues e da tabela vigente.

O botão **Falar com atendente** deve ser uma resposta rápida no modelo aprovado quando o proprietário quiser continuar a conversa no mesmo número. O webhook envia uma confirmação e pausa o menu por 24 horas para permitir o atendimento humano pelo aplicativo, desde que a Meta tenha habilitado a coexistência. A configuração de entrada começa desativada. No painel, o proprietário pode editar a saudação, dois rótulos/destinos HTTPS e o rótulo de atendimento. Ao receber uma mensagem, o bot envia até três opções; depois de uma opção de link, envia um botão que abre a página escolhida. O menu só reaparece após 24 horas, salvo quando o cliente o pede explicitamente por botão. Eventos recebidos são deduplicados pelo ID da mensagem.

Nenhum disparo de teste deve usar contatos reais sem aceite. Testar primeiro com uma conta descartável e um número controlado após a conexão oficial.
